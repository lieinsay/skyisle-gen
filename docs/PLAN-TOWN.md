# 聚落营建器设计稿：给一块地形、一个规模、一种风格，营建出一个建筑群

> 状态：**已拍板，实施中**（2026-09-28）；**第一步已做**（场地地形，DESIGN-NOTES 四点二十九），下一步华北集村。拍板：b 用 C++；g 同意，另写出扩展风格的方法（6.7），自定义风格的实现往后放；j 同意；
> n 往后放——目标指标先用资料与估值，OSM 标定以后再说；其余按默认。**先固定内置风格，扩展以后再说。**
> 用户补充：**建筑群的风格由用户决定**；这是一个**独立工具**，只是用了行星生成器的地形地貌与天气环境数据。
> 上游：`PLAN-SETTLE.md`（聚落层只给到「村 / 镇 / 散户 / 专业聚落 / 城的点位与户数」，100 m 一格）、`PLAN-ISLAND.md`（地形、水系、气候）。
> 起因：Zhouzhu 的铺村（17 m 方格从村心由近到远填满）铺出来的村子是一张实心圆饼，门一律朝村心——现实里没有哪种村子是这么长的。
> 写给一段时间没看项目的人：先读一、二、三、九节就够决定；资料与规则的对应在第四节，风格怎么写在第六节，算法在第七节。

## 一、要解决什么

聚落层告诉我们「这里有个 46 户的村」，但不知道这 46 户**住在哪、房子朝哪、谁家挨着谁、井和庙在哪、路怎么走**。
这些恰恰是「像不像一个真村子」的全部：华北平原的大集村、江南沿河的街村、川西田间的林盘、挪威山坡上的簇院、德国林间一户一条地的排村，
差别都在这一层。

聚落营建器做的事：**给一块地形（岛群里某个聚落的所在，或合成地形、外部高程图）、一个规模（宅院 / 小庄 / 村 / 集镇 / 城与都 / 专业聚落）、
一种风格（内置的现实风格，或自定义），生成一个建筑群**：路网、地块、宅院，每座建筑的位置、朝向、尺寸、层数、屋顶与功能，
外加井、塘、晒场、树、墙这些让它成为「聚落」而不是「一堆房子」的东西。

「考究」落在三件事上，每件都要能说出道理、能被校验量出来：

- **位置**：按地形、水、日照、风、田、漫水、崖缘选址；公共设施各有各的落位逻辑（庙在村口、祠在村前、市在路口、晒场在村边近田、磨在溪上、窑在下风）。
- **朝向**：按风格的一串有先后的规则（朝阳 / 背风 / 面街 / 面水 / 顺等高线 / 背山面水），「朝阳」按所在半球算。
- **功能**：每座建筑都有功能；户的种类（农户 / 市户 / 专业户）照上游；公共设施的数量按户数与覆盖半径定。

它是**行星生成器的一个子工具，不涉及游戏**：只出数据与预览图。算法写在 C++ 核心库里（游戏以子模块编这个库），将来游戏要用可以直接调，但那不在本稿范围。

## 三、与铁律和既有设计的关系

- **岛群生成器的下游，不回灌**：`skyisle_gen/town/` 只读岛群产物；`stages/`、`island/`、check、ninegrid、polity、culture 不得 import 它（pytest 静态断言，与 IS-iso 同式）。
  不改 settlements.json，也不改任何场。
- **原则乙**：见口径 m。高处可以落庙、祭台、望楼（功能与地形的物理理由：显眼、防守、不淹），不能落「贵户」。宅院大小的随机数与位置无关。
- **铁律五**：风格由调用者显式指定，**绝不从文化场的 argmax 推「这个村是什么风格」**。将来如要岛群自动带风格，只能按连续份额混合（口径 h 的混合风格就是给它留的口子），另开一批讨论。
- **铁律三（时代）**：现实风格横跨两千年（考工记、唐长安、明清徽州、中世纪欧洲），本工具不管时代。这个世界自己的风格，以后作为自定义风格来写。
- **随机数**：C++ 的 `entity_rng(seed, TOWN_STREAM = 22, "town:{节点}:{聚落}:{部件}")`；合成地形用 `"town:synth:{地形}:{部件}"`。
  **风格不进地形的随机流**：同一块地换风格，地面逐字节不变，画廊里的差别全是风格造成的。同输入逐字节相同（TP-det）。
- **配置**：`config/town/town.toml` 是工具自己的参数（地面细化、合成地形、出图，**与风格无关**）；`config/town/styles/base.toml` 是风格的全部键与默认值，`config/town/styles/<id>.toml` 是内置风格。都不进任何阶段的缓存 key（和 `[island]` 一样按需生成）。`--set town.键=值` 改工具参数，`--set style.键=值` 改风格参数。

## 四、资料怎么变成规则

各风格的数与出处在 `docs/TOWN-SOURCES.md`（14 种风格 + 形态量化指数，93 条来源）。这里只列「资料说了什么 → 生成器里变成什么」。

| # | 资料 | 结论 | 变成 |
|---|---|---|---|
| 1 | 鲁西奇《散村与集村》、金其铭《中国农村聚落地理》、Roberts & Wrathmell《英格兰乡村聚落图集》 | 聚落在「集」与「散」两极之间；往一处聚是因为取水难、防卫、公田轮作、宗族与官府；往开里散是因为处处有水、太平、各家田连片、地形破碎 | 风格的**形态算子权重**与**散度**参数；「每户一口井 / 全村几口井」「亲缘成簇的概率」 |
| 2 | Chisholm《Rural Settlement and Land Use》 | 田离家约 1 km 起收益明显下降，三四公里外不如另起聚落 | 选址评分「离自家田」；散居风格把宅放在田边、集村风格田在 1–2 km 内 |
| 3 | Hudson 1969（拓殖 → 扩散 → 竞争）、Hillier & Hanson 的 beady ring | 聚落是一户户长出来的：开基户占最好的地，分户就近，人多了间距趋匀；每个单元带一块自家空地挨着邻居长 | **生长型算子**的顺序：开基户 → 分户就近（亲缘簇）→ 填空；每个宅院自带院地 |
| 4 | 林地排村（Waldhufendorf）、江南街河、宿场町 | 房子贴着线状要素排：路、河、等高线；每户身后拖自家的地 | **街村 / 滨水 / 等高线 / 梳式算子**：先有线，再沿线切地块 |
| 5 | Emilien 等 2012《Procedural Generation of Villages on Arbitrary Terrains》 | 选址 = 若干场（坡、日照、离路离水）的加权和；路按坡度代价寻路、复用已有路 | **场地分析层**（兴趣图）+ **路网层**（坡度代价 A*、已有路打折、过水建桥） |
| 6 | 浦欣成《传统乡村聚落平面形态的量化方法研究》、王昀《传统聚落结构中的空间概念》、Clark–Evans 最近邻指数 | 住居的大小、朝向、间距分布可以量化，能区分聚落类型；外包长宽比 λ < 1.5 团状、> 2 带状，形状指数 S 圆为 1 | 每个风格写**目标指标区间**，生成后自检（TP-style 软项）；画廊目视；目标值用真实样本标定（口径 n） |
| 7 | 风水与各地民居研究 | 朝向不是一个角度，而是有先后的理由：采光（朝阳）、背风、面街（商业与交通）、面水、顺等高线（省土方）、背山面水 | **朝向规则链**（6.3）：每条规则带权重与容差，按风格排序 |
| 8 | 各地村落的公共设施研究 | 公共设施各有选址逻辑：庙在村口 / 水口，祠在村前正中面塘，市在路口，晒场在村边近田，磨在溪上，窑与铁匠在下风的村边，仓在高燥处 | **功能目录**（6.4）：每种功能的数量规则 + 选址谓词；风格把通用功能映射成本地建筑 |
| 9 | Conzen 城镇平面分析（burgage 条地）、《考工记》、唐长安里坊、明清县城 | 城镇的骨架是规划的街与地块制度：临街窄长条地、市场、城墙与门、中轴、坊 | **网格 / 围绿 / 城墙算子**与**沿街切条**；集镇与城的配方（7.9） |

## 五、架构（自下而上）

```
前端（Python）  命令 skyisle town · 风格加载（继承 / 覆盖 / 混合 → 扁平键）· 产物与出图 · 画廊 · 调试台
────────────── nanobind（_core.town_*）
编排            plan_site：按规模把下面各层串起来；唯一持有「正在长的方案」（占地栅格、路网、地块、宅院），向下传参
校验与指标      TP-* 硬项 · 风格目标软项 · 形态指标（密度、最近邻指数、朝向集中度、贴线率、路网 T / X 比……）
景观            树（防风林、林盘、村口大树）· 池塘（坑塘、风水塘、磨塘）· 晒场 · 墙与篱 · 田的分割线
宅院            宅院模板 → 各栋的占地、朝向、尺寸、层数、屋顶；台基与土方；贴地（挖填 / 台地 / 吊脚）
功能分配        功能目录：公共设施的数量与选址谓词；户（农 / 市 / 专业）→ 地块
地块            沿街切条 · 街坊递归切分 · 生长型的自带院地
结构            形态算子（团块生长、散居、围合单体、街村、滨水、等高线、梳式、围绿、网格、城墙修饰）· 路网（坡度代价寻路、复用、桥）
场地分析        坡度坡向 · 朝阳度 · 背风度 · 离水 / 离田 / 离崖 / 离泊场 · 漫水高差 · 地势（TPI）· 可建度 → 按风格权重合成兴趣图
场地地形        岛群窗口细化 / 合成地形 / 外部高程图 → 统一的 Site（高程、水面、河床、崖与虚空、田、地表、漫滩）
基础件          几何（有向矩形、多边形、折线、相交与包含）· 细栅格（采样、距离变换、光栅化、空间哈希）· 寻路（A*、代价场）；沿用 rng / config / grid
```

- **状态只在编排层**：下面每层都是「值进、值出」的纯函数（Site + 风格 + 当前方案 → 新增的路 / 地块 / 宅院），可以单独拿值测。
- **风格到 C++ 是一张扁平键值表**（和 `[island]` 一样由前端展平），C++ 不读 TOML。
- **形态算子是可插拔的**：每个算子实现同一接口（给结构骨架、给地块、给生长次序），风格按权重挑、可以组合（集镇 = 市街算子 + 村的算子）。

## 六、风格

### 6.1 风格文件长什么样

`config/town/styles/base.toml` 写全部键的默认值与注释；内置风格在 `config/town/styles/<id>.toml`，只写与 base 不同的键。
加载次序：base ← 风格 ← `--set style.键=值`（自定义风格的 `extends` 链见 6.7，往后放）。下面是江南水乡的节选：

```toml
[meta]
id = "jiangnan"
name = "江南水乡"
region = "太湖流域"
extends = "base"
sources = ["TOWN-SOURCES §2"]           # 数的出处；「估」的在注释里标

[site]                                # 村心在上游点位 300 m 内按兴趣图挑
weights = { water = 3.0, flat = 1.5, flood = -2.0, farmland = -1.0, sun = 0.5 }

[village]
operators = { waterfront = 0.7, street = 0.3 }   # 形态算子的权重
households_per_compound = [1, 1]
gross_m2_per_household = 250          # 连路带院的毛用地，定窗口大小与密度（估）

[waterfront]
mode = "前街后河"                      # 前街后河 | 前河后街 | 两街夹河
river_width_m = [8, 20]               # 市河（估）
bridge_spacing_m = [80, 200]          # 估，按周庄的桥密度
steps_per_households = 3              # 几户一个河埠头（估）

[street]
width_m = { "街" = [2.0, 2.5], "弄" = [0.8, 2.0] }   # 廊棚街；街弄 / 水弄 / 陪弄
bay_m = [3, 4]                        # 每间面阔
bays = { 3 = 0.7, 5 = 0.3 }           # 开间取奇数
depth_per_jin_m = [5, 13]             # 一进的进深
jin = { 1 = 0.5, 2 = 0.35, 3 = 0.15 } # 几进（估）
setback_m = 0
contiguous = true                     # 连排，山墙相贴

[orient]                              # 朝向规则链（6.3）
```

### 6.3 朝向规则链

每座主屋（及宅院整体）的朝向由风格的一串规则决定，每条规则给出「想朝哪」与「多想」：

| 规则 | 想朝哪 | 典型容差 |
|---|---|---|
| `sun` 朝阳 | 朝赤道方向（北半球正南）；可带偏角（风格参数） | 严 ±10°，松 ±45° |
| `wind` 背风 | 背对盛行冬风（来自 climate.json 冬季风向） | ±60° |
| `street` 面街 | 垂直于最近的街，门朝街 | ±10° |
| `gable_street` 山墙朝街 | 屋脊垂直于街（中欧 Giebelständig） | ±10° |
| `water` 面水 | 朝最近的河 / 湖 / 塘 | ±30° |
| `downslope` 顺坡 | 朝下坡（面阔顺等高线，省土方、有视野） | ±30° |
| `back_hill_face_water` 背山面水 | 背后地势高、前方有水 | 评分式 |
| `yard` 朝院 | 簇院里的各栋朝共同的院子（北欧 tun、四合院的厢房） | ±15° |
| `baseline` 朝前沿 | 梳式里全部朝前沿 | ±5° |
| `fixed` 定角 | 写死角度（少用） | — |

求解：在候选角度上（每 5°）算 Σ 权重 × 满足度（容差内为 1、容差外按余弦衰减），取最大；风格可要求量化（`snap_deg`，如华北院落整齐排列）。
门的位置另有规则：华北合院的门开在前沿的左角（站在院里面朝前沿时的左手边；坐北朝南即东南「巽位」）；南半球整座院子转 180°，门随之在西北角。

### 6.5 宅院模板

宅院 = 一户（或一簇）的地块 + 几栋房 + 院 + 墙 / 篱 + 菜园。模板在地块局部坐标里描述各栋的角色、相对位置、尺寸区间与朝向（主屋朝前沿、厢房朝院……），
求解时按地块缩放、在地形上找台基高程、查挖填量：超过风格上限就试台地、吊脚（风格允许时）、转 90°，都不行就换位。

首批模板（尺寸区间在风格卡里）：四合院、三合院、一字屋带院、天井屋（一进 / 多进）、前店后宅、三间两廊、窑院（靠崖窑 / 下沉式）、林盘簇院、
北欧簇院（主屋 + 仓楼 + 畜舍 + 灶房 + 蒸浴房围一个院）、中欧三合院 / 四合院（Dreiseithof / Vierseithof）、英格兰 toft & croft、burgage 临街屋、土楼环屋。

- 林地排村：每户一条地，临街宽约 100 m，向后可达 2.4 km（宅—园—田—牧—林），房沿溪或路排成一线，地条垂直于屋线。
- 街村：两排农庄夹一条村路。绿地村：眼形公地宽 30–100 × 长 150–600 m（估），房屋檐面朝公地，畜舍谷仓在地块后部，村外一圈农道；公地上有教堂、学校、铁匠、池塘。环村：3–10 户马蹄形围一个椭圆广场、只有一个入口。团村：无规划，围池塘或空地，外有村界（Etter）。
- 宅院：三合院（Dreiseithof：住宅与畜舍山墙朝街、相对而立，谷仓横封后侧）、四合院、临街门墙（Torwand）；地块 25–40 × 40–80 m（估）。
- 朝向：山墙朝街（Giebelständig）或檐面朝街 / 朝公地，按子预设。
- 目标：林地排村 λ > 3、地条宽变异系数 < 0.2；绿地村房屋朝公地 ≥ 80%。

**11 英格兰集村** `england`
- 形态：规划型——同宽的 toft + croft 沿主路两侧排开，后有背巷；绿地变体；教堂与庄园占村端的大地块；24–50 户。
- 宅院：toft（房 + 院）+ croft（后园约 0.5 英亩），面宽 15–25 × 进深 60–120 m（估）；长屋 14.2 × 4.3 m，台基 ≤ 20 × 10 m。
- 朝向：面街（长边顺街）。景观：开放田 2–3 块大田，条田（一 furlong 约 201 m 长）画在窗口内的田里。
- 目标：地块面宽变异系数 < 0.25；主路型 λ > 2。

**12 欧洲中世纪市镇** `eu_town`
- 形态：街村 + 市场（纺锤 / 三角 / 矩形，宽 20–60 × 长 100–300 m，估），教堂贴市场一侧；城墙可选，门 2–4 座对准主干道，城周 1–3 km（估）。
- 地块：burgage 面宽 8.5–15 m（2–3 perch；Alnwick 多为 28 ft），有 ¾、1¼ 宽的分合；进深 60–100 m。
- 宅院：临街一开间宽的屋，侧边通道通后地；后地是园圃、畜栏、作坊，**按「年代」参数逐步盖满**（Conzen 所说的地块内加密）。
- 目标：临街面宽的众数落在 8.5–15 m；市场周边建筑面街 ≥ 90%。

**13 地中海山城** `med_hill`
- 形态：团块生长；选址山顶 / 山脊 / 坡嘴（TPI 高、易守）；最外一圈房屋连成墙，或顺山形排成椭圆环（Kastro）；教堂与城堡两节点，街道放射或成环；小广场 1–3 个。
- 宅院：单栋约 30 m²、1–2 层；石屋、白墙（材料标签）。
- 朝向：顺等高线、朝下坡。街巷：1.5–3.5 m、H/W 2–4（估），局部覆顶。
- 目标：覆盖率 60–80%（估）；λ < 1.5。

**14 日本** `japan`（子预设：砺波散居村 / 宿場町 / 環濠集落）
- 砺波散居村：一户一处，屋距 50–100 m（均匀推算约 180 m），每户被自家水田围着；屋敷林（カイニョ）在冬季风的上风侧最厚（原地是西南），入口开在林木少的一侧。
- 宿場町：沿街道约 1 km，道宽 2.7–6.4 m；短冊形地割，间口 2–5 間（3.6–9 m）× 进深 15–30 間（估）；切妻平入、中二階；本陣与問屋居中段，两端神社，寺在一侧；鍵の手拐弯。
- 環濠集落：约 260 m 见方，濠宽 7–15 m、深 2–3 m，40–50 户，村内路曲折。
- 目标：散居村 R ≥ 1；宿場町 λ > 5。


### 6.7 风格怎么扩展（方法；实现往后放）

加一种风格分四档，越往下越要动代码。**前三档只写数据**：

| 档 | 要加什么 | 怎么加 | 动代码吗 |
|---|---|---|---|
| 1 | 只是参数不同（巷宽、宅基尺寸、朝向容差、算子权重、设施的数量） | 新写一份 TOML：`extends = "某内置风格"`，只写不同的键；`--style 路径` 就能用 | 不动 |
| 2 | 新的宅院样式（比如一种新的合院） | 在风格文件的 `[compound.templates.<名>]` 里写各栋的角色、相对位置、尺寸区间、朝向（6.5 的格式） | 不动 |
| 3 | 新的公共设施（比如一种新的庙、磨坊、市场） | 在 `config/town/functions.toml` 加一行（数量规则 + 选址谓词，谓词只能用 6.4 里已有的那些场），风格里映射 | 不动 |
| 4 | 新的布局骨架（现有十种形态算子都表达不了的排法） | 在 C++ 里加一个形态算子，实现统一接口（给骨架、给地块、给生长次序），风格按名字引用 | 要动 |

- **混合风格**：`--style A:0.7,B:0.3`——数值键按权重插值，类别表（算子权重、宅院模板、功能映射）按权重合并；朝向规则链取并集、权重相乘。
- **来源与标定**：新风格也按风格卡的格式写出处（或标「估」）；有真实样本时按口径 n 量指标、写回 `[targets]`。
- **检查**：`skyisle town style check <文件>` 查键名拼错、区间倒置、引用了不存在的模板 / 功能 / 算子；生成时照样跑 TP-* 全套。

## 七、各模块设计

### 7.1 场地地形（Site）

> 第一步落地时与下面几条的出入（以 DESIGN-NOTES 四点二十九为准）：窗口余量 250 m、毛用地暂按规模取（风格还没有）；河槽先填平再插值、只在细栅格上按河宽刻；
> 漫水按河的大小缩、且只在坡 < 4° 处；地表类别用软投票而不是最近邻 + 抖动；噪声按来源坐标取，窗口只决定裁多大。

- **窗口**：以聚落点为心，半径 = 1.6 × √(户数 × 毛用地 / π) + 200 m（毛用地来自风格）；宅院 60 m、小庄 250 m 起。城的窗口可以跨虚空，把郭所在的邻岛一并裁进来。
- **高程**：100 m 栅格双三次插值；加 8–64 m 波长的细节噪声，振幅 = 夹(0.3, 4 m, k × 局地起伏)，河道与河岸带内衰减到 0（保证河床单调）。
- **河**：rivers.json 的中心线（格心折线）先 Chaikin 平滑三遍，河宽照点上的值；水面 = 河床 + 水深，沿线强制单调下降；河岸按风格无关的剖面压到水面 + 干舷。
  溪涧（级别 0）同法，标季节性。湖：0 / 1 掩码双线性后取 0.5 等值线，加一点边界噪声。
- **崖与虚空**：岛号掩码同法取岸线；岸缘内 `cliff_setback_m`（默认 15 m）不可建。
- **田与地表**：上游 fields（settlements.png 的 1 / 2）与 landcover 按最近邻放大，类别边界加噪声去方格；漫滩照上游，再加「离水面高差 < 2 m」。
- **合成地形**：十种预设（口径 c），每种有自己的参数（坡度、朝向、河宽、谷宽……）与种子；合成时照样给出 Site 的全部字段（田按「平、近水、非漫滩」自动划）。
- **外部高程图**：16 位 PNG + `--res` + 可选水面 PNG。

### 7.2 场地分析

全部是 Site 上的栅格，纯函数：坡度、坡向、**朝阳度**（冬至正午太阳矢量与地表法线的夹角，半球按节点纬度）、**背风度**（冬季盛行风的上风向地平角）、
TPI（50 m 与 200 m 两个尺度的相对高程：脊、坡、谷、顶）、离河 / 湖 / 溪 / 井、离田、离崖、离泊场、漫水高差、可建度（坡 ≤ 风格上限、非水、非崖、非漫滩除非风格允许吊脚）。
**兴趣图** = Σ 风格权重 × 归一化后的各场（Emilien 的做法）；每种用途一张（宅、公共建筑、晒场……）。

### 7.3 路网

- 图：节点 + 边（折线、等级：干道 / 街 / 巷 / 田间道 / 山径、宽度），外加桥。
- 寻路：细栅格上 16 邻域 A*，代价 = 长度 × (1 + k × (坡 / 风格最大坡)²) + 过水代价（只在窄处、垂直过河，建桥）+ 压田代价 − **已有路折扣**（路会合并、不平行乱跑）；
  超过最大坡的方向不可走，之字路自然长出来。结果 Douglas–Peucker 简化 + Chaikin 平滑。
- 主干先连：村心 ↔ 泊场、村心 ↔ 水源、村心 ↔ 田、村心 ↔ 窗口边上相邻聚落的方向、村心 ↔ 桥头。

### 7.4 地块

- **沿街切条**：沿街的偏移线按弧长走，开间从风格分布抽，垂直切出条地，进深到后界或障碍；每隔几块留一条巷。
- **街坊切分**：网格的坊按有向包围盒递归对切（Vanegas 2012 的 OBB 切分），直到面积与临街都达标。
- **生长型的院地**：地块就是宅院的外包加院地缓冲，不预先切分。
- 地块记录：多边形、临街边与出入点、面积、坡度统计、归属户。

### 7.5 功能分配

次序：上游锚点（泊场、取水点 / 蓄水池、桥头）→ 核心公共（祭祀、政、市）→ 公用（井、晒场、磨、仓）→ 户 → 工（下风、村边）。
每种功能按数量规则算出要几座，逐座在候选（地块或空地）上按选址谓词评分取最高。户按种类进地块：市户上主街临街（前店后宅），农户靠田那一侧，专业户靠各自的资源点。

### 7.6 宅院

模板实例化（6.5）→ 朝向求解（6.3）→ 台基：足下地面的中位 + 台高，挖填量 = Σ |地面 − 台基|；超限时试台地、吊脚、转向、换位 → 占地写进占地栅格（带间距缓冲）→ 门接路。
每栋建筑记：功能、角色、中心、朝向、面阔、进深、层数、檐高、屋顶类型与坡度、材料标签、台基高程、挖填量。

### 7.7 景观

防风林（风格允许时，落在冬风上风侧，カイニョ式）、林盘的一圈竹木、村口 / 水口大树、公地的树；坑塘（取土成塘，村边）、风水塘（祠前半月塘）、磨塘；
晒场、菜园（屋后）、墙与篱；田的分割线（条田、排村身后的长条、水田埂按等高线），只在窗口内、只画线。

### 7.8 户与亲缘

- 户的种类与数目照上游（农户、市户、专业户）；合成地形时由命令行给。
- **亲缘树**：开基户 1–3 户（风格），之后每户按 `kin_p` 从已有户里挑一个父户，否则算外来户；生长型算子据此成簇（同一房支挨着住），散居算子据此决定一个林盘里住几户。
- **多户一院**：`households_per_compound` 的分布决定一个宅院住几户（林盘 1–10、土楼 30–80、华北多为 1）。
- 户只有编号、种类、父户与所在宅院，不带任何身份等级（原则乙）。

## 十、风险

- **风格参数失真**：资料里的数是某地某时的，有的只能估。风格卡里每个数标出处或「估」；画廊目视为准，TP-style 只是护栏。
- **生长型算子调不像**（太规整或太乱）：先把华北一种调到像，再推广；算子接口在第三步加前三个风格时回头修。
- **细化地形与别处的地面不一致**：游戏有自己的细化。产物带 site.npz 与每栋的台基高程，谁用谁对齐。
- **城的规模**：都可到一万五千户。C++ + 2 m 占地栅格 + 空间哈希，目标一座都 < 30 s、一个村 < 1 s。
- **跨岛之郭**：窗口跨虚空、路只能走索桥（岸距 ≤ 100 m 的才有桥），很多都没有郭可摊；这时郭留空并在产物里注明。
- **合成地形与岛群地形的差距**：风格在合成地形上调好，到真实岛上可能挤不下（岛上坡陡、田碎）。第二步起就同时看合成与 #2051 两种。
